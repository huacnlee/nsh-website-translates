# Отчёт о производительности

Сколько стоят приложения NSH, в измерениях. Как NSH обеспечивает их быстродействие и как измерить собственное приложение, описано в разделе [Производительность](./performance.md).

<a id="baselines"></a>

## Базовые показатели

По собственным замерам NSH (Apple silicon, если не указано иное):

| Сценарий | Результаты |
|---|---|
| Приложение-счётчик, headless (debug) | Первый кадр ~0,5–0,65 мс (58 операций / 49 элементов монтирования); одно нажатие ~0,15 мс |
| Приложение-счётчик, Mac Catalyst (release) | Первый кадр ~1,05–1,15 мс (около 0,7 мс уходит на первую раскладку 10 текстов через CoreText); одно нажатие ~0,12 мс |
| Список фото в Gallery, headless (debug) | Первый кадр: 653 операции / 224 узла, ~2,7 мс |
| Прокрутка списка фото, Catalyst (release) | Перепривязка одной строки при медленной прокрутке ~0,4 мс; целый экран из ~32 строк при быстром броске 0,9–1,6 мс |
| Прокрутка списка фото, эмулятор Android (arm64, release) | Перепривязка одной строки ~0,3–0,4 мс (JS ~60 мкс) |
| Запуск движка (release) | ~75–155 мкс; глобальные API (`fetch`, `URL`, ...) ничего не стоят до первого использования, затем ~90 мкс |
| Hot reload | ~120 мс от сохранения файла до запуска новой версии; применение обновления 0,2–0,5 мс |

### Каждая страница

Каждая страница Gallery при открытии и во время прокрутки тестом, в окне 1200 × 800 на дисплее 144 Гц (на той же машине). NSH рисует кадр только тогда, когда на экране что-то меняется, поэтому *FPS* здесь — это частота в то время, пока что-то движется: один кадр на медианный интервал между отрисованными кадрами (`perf.py`, `moving`); при 144 Гц дисплея каждый кадр анимации или прокрутки приходит через одно обновление после предыдущего. *Дольше одного обновления* — доля кадров, которые заняли больше времени, чем одно обновление (6,9 мс). GIF и WebP на странице Images воспроизводятся с собственной частотой кадров (здесь около 50 FPS), так же как и видео. Страницы Physics, Overlays и Menus короткие: в окне 1200 × 800 прокрутка доходит до их конца за несколько кадров, поэтому они измерены в окне 900 × 500, где есть место для прокрутки.

### Память

В покое, через 3 с после запуска (release-раннеры, окно 480 × 640). *Private* — память, которой владеет только сам процесс (USS); *resident* добавляет страницы разделяемых библиотек (GTK, драйвер GPU), которые совместно используют все приложения GTK на машине:

<div class="data-table">

| Приложение | Рендерер | Private (USS) | Resident (RSS) |
|---|---|---|---|
| Приложение на Rust (`nsh init --template rust`) | GL (`ngl`) | ~49 МБ | ~142 МБ |
| Приложение на Rust | Cairo (`GSK_RENDERER=cairo`) | ~28 МБ | ~95 МБ |
| Счётчик на TSX (`examples/counter`) | GL | ~79 МБ | ~166 МБ |
| Окно GTK 4 с одной меткой, для сравнения | Vulkan / Cairo | ~62 / ~40 МБ | ~132 / ~109 МБ |

</div>

Повторное посещение страницы не добавляет памяти; первое посещение страницы увеличивает процесс на то, что он намеренно кэширует (декодированные изображения, не более 128 МБ), и на библиотеки, которые загружаются при первом использовании (WebKitGTK для веб-представлений).

### Размер приложения

Приложение hello world, созданное командой `nsh init` с каждым шаблоном, и два приложения, которыми пользуются люди, в том виде, как `nsh package --target linux` собирает их для x86_64. Раннер — единственный исполняемый файл приложения; архив — это `.tar.gz`, в котором оно поставляется. Hello world собраны с оптимизацией на этапе компоновки (link-time optimization) и со снятыми символами (`CARGO_PROFILE_RELEASE_LTO=fat`, `CARGO_PROFILE_RELEASE_CODEGEN_UNITS=1`, `CARGO_PROFILE_RELEASE_STRIP=true`):

<div class="data-table">

| Приложение | Язык | Раннер | Архив |
|---|---|---|---|
| Hello world (`--template rust`) | Rust | 16,5 МБ | 7,5 МБ |
| Hello world (`--template ts`) | TSX, на QuickJS | 25,7 МБ | 11,6 МБ |
| Hello world (`--template mixed`) | TSX и крейт Rust | 25,8 МБ | 11,7 МБ |
| [sysmon](https://github.com/huacnlee/sysmon) 0.1.3 | Rust | 20,9 МБ, со снятыми символами | 9,7 МБ |
| [Omasend](https://github.com/huacnlee/omasend) 0.2.0 | Rust | 22,3 МБ | 9,8 МБ |

</div>

Раннеры TSX содержат среду выполнения QuickJS, нативные модули и рендерер; собственный код приложения — это его бандл рядом с раннером, для hello world меньше 1 КБ.

Что определяет эти цифры:

- **Рендерер**: с драйвером NVIDIA NSH рисует через GL-рендерер GSK, кадры которого обходятся в долю от стоимости кадров рендерера Vulkan (демо Animations: ~1 мс отрисовки на кадр вместо ~9,5 мс). Выбор при этом по-прежнему остаётся за `GSK_RENDERER`.
- **Растеризация Canvas**: каждый canvas растеризуется один раз в тайлы 256 px, которые хранятся на GPU. Анимированное значение перерисовывает только ту область, которую покрывают читающие его операции, поверх сохранённых пикселей статической части рисунка; canvas вне поля зрения ждёт, пока его не прокрутят в видимую область.
- **Пути, отложенные один раз**: `fillRect` и `fillText` после длинного пути оставляют его на месте, пока он снова не понадобится (линия из 400 точек, затем 240 столбцов: 0,63 мс).

### Память

В покое, через 3 с после запуска (release-раннеры). *Footprint* — память, которую macOS засчитывает процессу (то, что показывает Activity Monitor); *resident* добавляет страницы разделяемых библиотек системы:

<div class="data-table">

| Приложение | Окно | Footprint | Resident (RSS) |
|---|---|---|---|
| Приложение на Rust (`nsh init --template rust`) | 1200 × 800 | ~19 МБ | ~86 МБ |
| Счётчик на TSX (`examples/counter`) | 1200 × 800 | ~20 МБ | ~89 МБ |
| Окно AppKit с одной меткой, для сравнения | 480 × 640 | ~17 МБ | ~80 МБ |

</div>

В ходе обхода Gallery процесс занимает 84–230 МБ до страницы Canvas и ~350–360 МБ начиная со страницы Text View — с учётом того, что он намеренно кэширует (декодированные изображения, не более 128 МБ; документы страницы Text View), и фреймворков, которые загружаются при первом использовании (WebKit для веб-представлений); растры страницы Canvas, до ~310 МБ при трёх canvas на экране одновременно, освобождаются при закрытии страницы.

### Размер приложения

Hello world-приложения, созданные `nsh init` с каждым шаблоном, в том виде, в каком `nsh package --target macos` собирает их для Apple
silicon (arm64) с оптимизацией на этапе компоновки и удалением символов, как на Linux, а также два приложения выше в том виде, в каком они поставляются для Apple
silicon. Исполняемый файл — это раннер внутри `.app`; zip — это `.app` в сжатом виде (`ditto -c -k`):

<div class="data-table">

| Приложение | Язык | Исполняемый файл | В zip `.app` |
|---|---|---|---|
| Hello world (`--template rust`) | Rust | 12,4 МБ | 6,0 МБ |
| Hello world (`--template ts`) | TSX на QuickJS | 19,8 МБ | 9,5 МБ |
| Hello world (`--template mixed`) | TSX и крейт Rust | 19,8 МБ | 9,5 МБ |
| [sysmon](https://github.com/huacnlee/sysmon) 0.1.3 | Rust | 21,6 МБ | 8,4 МБ (`.tar.gz` его релиза) |
| [Omasend](https://github.com/huacnlee/omasend) 0.2.0 | Rust | 18,4 МБ | 9,7 МБ (`.tar.gz` его релиза) |

</div>

Чем обусловлены эти цифры:

- **Кадры только при изменениях**: display link тикает, пока идёт нативная анимация, и останавливается вместе с ней; анимация
  останавливается вместе со своей страницей (удаление её представления завершает его keyframes, цикл останавливается в `cleanup` своего компонента).
- **Canvas рисуются там, где это дешевле всего**: canvas, который перерисовывается часто (анимация, живые данные), рисуется в потоках Core
  Animation (`drawsAsynchronously`), что освобождает главный поток; canvas, который перерисовывается время от времени, рисуется
  сразу, без графической памяти, которую удерживает асинхронная отрисовка. Анимированное значение перерисовывает только ту область, которую
  покрывают операции, читающие это значение.
- **Статичные части canvas сохраняются**: когда рисунок остаётся неизменным, длинная часть перед первой анимированной операцией
  сохраняется как слой; каждый кадр рисует этот слой и воспроизводит заново только анимированный остаток, сразу в главном потоке (gauge, часы и точечная матрица
  на странице Canvas: никакой работы GPU и вдвое меньше памяти).
- **Содержимое рисуется при изменении**: тексты и canvas рисуются в собственные слои и перерисовываются, когда меняются их содержимое или
  размер, а не когда они перемещаются или прокручиваются.

## Windows (Win32, Direct2D)

Измерения проведены на настольном компьютере с Windows 11 (Intel Core i7-13700KF, 32 ГБ, NVIDIA GeForce RTX 3060 Ti) на 4K-дисплее 144 Гц с масштабом
150%, релизные сборки, галерея в окне 1200 × 800 (1800 × 1200 пикселей), каждое показание снималось автоматически
с помощью `examples/gallery/tools/perf.py` (`nsh test --target windows --fps`, одна строка в секунду; CPU — весь процесс, в
процентах от одного ядра). Фазы — это работа главного потока за кадр: *paint* (Direct2D рисует окно) и, внутри
неё, *canvas* (запись и воспроизведение рисунков).

> против 5–13%, Gestures 36% против 1–5%). Кадр в Windows перерисовывает средствами Direct2D в главном потоке каждое представление
> в изменившихся областях: растущее кольцо перерисовывает карточку под собой в каждом кадре. В macOS Core Animation
> перемещает, масштабирует и затеняет сохранённые слои на GPU, не перерисовывая их, а в Linux GSK сохраняет
> render nodes того, что не изменилось. Кроме того, в цифрах учтены 144 кадра в секунду при 1800 × 1200 пикселей.

### Память

В покое, через 3 с после запуска (релизные раннеры, окно 1200 × 800). *Приватный рабочий набор* — это память, которую процесс
использует один (столбец «Память» в Диспетчере задач); *приватные байты* — то, что он зафиксировал; *рабочий набор* добавляет страницы
системных библиотек, которые он делит с другими процессами (Direct3D, Direct2D, DirectWrite, драйвер GPU):

<div class="data-table">

| Приложение | Приватный рабочий набор | Приватные байты | Рабочий набор |
|---|---|---|---|
| Приложение на Rust (`nsh init --template rust`) | ~14 МБ | ~60 МБ | ~53–71 МБ |
| Счётчик на TSX (`examples/counter`) | ~15 МБ | ~61 МБ | ~56–71 МБ |

</div>

За время тура по галерее рабочий набор составляет ~108–115 МБ на Stocks, ~230 МБ начиная со страницы Canvas, ~320–340 МБ начиная со
страницы Text View и ~390–405 МБ после того, как Web and video откроет WebView2 (чьи страницы работают в собственных процессах WebView2),
вместе с тем, что он кэширует намеренно (декодированные изображения, не более 128 МБ; документы страницы Text View).

<a id="app-size-2"></a>

### Размер приложения

Hello world-приложения, созданные `nsh init` с каждым шаблоном, в том виде, в каком `nsh package --target windows` собирает их для x86_64
(раннеры на Rust с оптимизацией на этапе компоновки и удалением символов, как на Linux). Исполняемый файл — это `<Name>.exe` приложения;
zip — это `.zip`, записанный рядом с его каталогом:

<div class="data-table">

| Приложение | Язык | Исполняемый файл | Zip |
|---|---|---|---|
| Hello world (`--template rust`) | Rust | 15,0 МБ | 6,7 МБ |
| Hello world (`--template ts`) | TSX на QuickJS | 28,6 МБ | 12,4 МБ |
| Hello world (`--template mixed`) | TSX и крейт Rust | 26,3 МБ | 11,5 МБ |

</div>

Чем обусловлены эти цифры:

- **Кадры только при изменениях и рисуются только там, где изменилось**: тикер, синхронизированный с композитором, работает, пока идёт нативная
  анимация, переход или callback кадра. Кадр рисует области изменившихся представлений (где они
  были и где находятся), поверх пикселей, которые хранит окно, и передаёт композитору только их (Stocks:
  ~34 представления за кадр).
- **Canvas записывают свою анимированную часть**: рисунок записывается как списки команд Direct2D, векторный и чёткий при любом
  масштабе. Когда анимированное значение меняется, заново записываются только операции, начиная с первой, которая читает анимированное значение; то,
  что идёт до неё, сохраняется (Stocks: ~26 мс записи в секунду для 22 пульсирующих спарклайнов и
  графика).
- **Рисуется только то, что видно**: дочерние элементы scroll view или clipping view, находящиеся вне поля зрения, исключаются из
  кадра, а представления без собственного содержимого рисуют только фон и границу.

## Измерение приложения

Чтобы измерить приложение так же, запустите его тесты или шаги с помощью `--fps` и `-v` на `--target linux`, `macos`, `windows` или `ios`:

```sh
cargo build --release -p nsh-cli
python3 examples/gallery/tools/perf.py --target macos --only Stocks,Canvas   # the gallery, page by page
echo 'await app.wait(5000)' | nsh -v test App.tsx --target linux --fps        # any app
```
